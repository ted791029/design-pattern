# 設計重點

## Scene 導覽圖（Scene Graph）可擴充

- **怎麼做到**：`SceneManager` 用註冊與 `link(...)` 定義路徑，`Scene` 透過 `resolveChildren(...)` 動態組子選單。
- **帶來的彈性**：加新場景（例如 `Export words`）只要註冊 + `link`，不用改既有父場景類別。

## 場景建立責任解耦（SceneFactory）

- **怎麼做到**：`SceneManager.register(SceneId, SceneFactory)`，由工廠建立場景，不在管理器硬編碼 `new`。
- **帶來的彈性**：新增場景型別不影響核心框架，符合開放封閉原則。

## Default Menu Option 可插拔

- **怎麼做到**：`DefaultMenuOptionKey` + `DefaultMenuOptionFactory` 註冊機制。
- **帶來的彈性**：新增預設選項（不只 `/B`、`/ESC`）不用改 `Scene` 基底流程，只要新增 key + factory + 註冊。

## 選單可動態顯示/隱藏（Dynamic Menu Option）

- **怎麼做到**：`MenuOption` 提供 `isVisible()/setVisible()`，`Command` 與 `Scene` 都支援可見性；`Menu` 在顯示與解析指令時都會過濾 `visible=false` 的選項。
- **帶來的彈性**：同一個場景可依當下狀態切換可用操作（例如結果頁只顯示 `Continue/End`），不用寫多個重複場景。

## 場景 UI 組裝採模板方法

- **怎麼做到**：`Scene` 統一 `render` 流程（breadcrumbs / messenger / menu / prompt），子類只覆寫 hook（`renderMessenger`、`renderPrompt`、`contributeMenuOptions`...）。
- **帶來的彈性**：共用流程固定、場景差異集中在覆寫點，新增場景時重複碼少、風險低。

## 生命週期策略可配置

- **怎麼做到**：`LifecycleType` + `distance` 由每個 scene 宣告，`SceneManager.dispose()` 統一執行清理策略。
- **帶來的彈性**：不同場景可自由換成 `NEVER_CLEAR` / `CLEAR_ON_LEAVE` / `DISTANCE_BASED`，不用重寫場景切換主邏輯。

## 查字技術可替換（Strategy）

- **怎麼做到**：透過 `DictionaryQueryTechnique` 抽象介面注入 `AppContext`，目前用 `LocalJsonDictionaryAdapter`。
- **帶來的彈性**：未來改爬蟲/API，只換 adapter，不動場景與核心框架。

## Scene ID 型別化（enum）

- **怎麼做到**：用 `SceneId` 取代字串，註冊/link/push 全部改 `enum`。
- **帶來的彈性**：降低 typo 風險、重構安全性高，新增/修改 ID 有編譯器保護。

## 場景狀態集中於 AppContext（跨場景共享）

- **怎麼做到**：以 `AppContextKey` + `tempData` 統一保存暫態流程資料（如 quiz 進度、搜尋結果、latest score），場景與 command 共同讀寫。
- **帶來的彈性**：狀態不綁死在單一 scene instance，可讓 command 直接驅動流程，並且更容易調整生命週期清理策略。

## Default 與自訂選單分層覆寫

- **怎麼做到**：`Scene.renderMenu()` 統一組裝「graph 子場景 + 場景自訂選項 + default 選項」，並用 `hiddenDefaultMenuOptions()` 讓各場景聲明要隱藏哪些 default key。
- **帶來的彈性**：新增 default option 不影響現有場景；既有場景若要調整顯示，只覆寫隱藏集合即可，不用整段重寫 menu。
